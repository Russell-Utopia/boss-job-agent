# THROWAWAY WEB PROTOTYPE

> 这是一次可丢弃的 Web 交互原型。岗位、Worker 和正式策略版本都只存在于当前 Python 进程内；生成出的策略候选稿只存在于当前浏览器页面会话，不写文件、不由后台保存或恢复。不包含生产 Go 业务逻辑，不连接 BOSS，不读取真实在线简历，不执行任何真实首次沟通。

## 运行

```bash
./throwaway-prototypes/run-web
```

打开：<http://127.0.0.1:4177/prototype/workbench?view=jobs>

只有一个收敛后的产品结构：

- `?view=jobs&jobPage=1&jobPageSize=10`：岗位。页首直接显示岗位发现、鉴定、首次沟通三块运行概况；下方筛选和分页查看全局岗位，可选择每页 10 / 20 / 50 / 100 条，并发起人工复核、重新鉴定、模拟沟通或真实发送。
- `?view=assessment`：岗位鉴定。显式维护当前策略、生成新策略和自动鉴定设置；“AI 同时鉴定数”用正整数输入框直接填写，首次默认 5，但不把 5 误作可配置上限。
- `?view=outreach`：首次沟通。配置自动沟通、Simulation / Real、固定招呼语，以及可预设或自定义的发送时间窗。
- `?view=resume`：在线简历。唯一的手工刷新入口。

TUI 和旧的三套 Web 布局已经删除；它们没有进入生产分支。

## 交互主线

```text
岗位发现
  → 岗位/JD 保存到全局岗位列表
  → 自动或手工安排鉴定
  → 自动或手工安排首次沟通
```

岗位发现是一个可恢复的搜索运行；同一时间最多有一个未结束运行。岗位页顶部可以继续、暂停或提前结束当前运行；运行完成或提前结束后才出现“创建岗位发现”入口。创建确认页说明本次使用的已保存在线简历版本、搜索范围和非阻断设置提示，并明确发现结果会先进入岗位列表。

不再设置独立的“执行情况”页。岗位页顶部三块概况统一使用“已完成 / 总数 + 进度条”：岗位发现按搜索范围、岗位鉴定按已完成鉴定、首次沟通按已真实沟通统计；点击“筛出”直接作用于同页岗位列表。岗位列表可选择每页 10 / 20 / 50 / 100 条；切换分页大小或筛选条件都会回到第一页。

岗位鉴定和首次沟通的执行进度是全局岗位上的状态，不建立独立任务表。岗位表把“AI 鉴定”和“人工结论”拆为独立列：人工列直接显示“未复核 / 已复核·适合 / 已复核·不适合 / 待重新复核”，不要求用户从操作资格说明里反推是否审核过。人工结论可按“已复核、未复核、人工适合、人工不适合、待重新复核”筛选。每个岗位行直接显示“人工复核 / 重新鉴定 / 模拟沟通 / 真实发送”，可处理时直接执行，不可处理时按钮禁用并通过悬停说明原因。批量处理只用于一次操作多个岗位：先选择动作，再显示对应复选框；“全选”只选择当前页可选岗位。单条和批量提交都会由后台模拟状态机重新校验。界面不暴露“入队/未入队”术语：`not_queued` 显示为“尚未安排”，`pending` 显示为“待鉴定”或“等待模拟/等待真实沟通”。

人工复核不是 `needs_user_confirmation` 的专用入口。AI 判为“适合”或“不适合”的岗位同样可以人工复核；求职者也可以再次复核已有人工结论。复核弹窗左侧展示当前 JD 快照的岗位名称、公司、城市、薪资、完整工作职责和任职要求，右侧展示 AI 结论、理由、实际使用版本及当前人工结论；人工必须依据当前 JD 判断，而不是只看 AI 摘要。保存后，基于当前 JD 的最新人工结论优先于 AI，但不会修改 AI 原结论。岗位页可以先筛选“AI 不适合”，再批量进入逐个人工复核；“建议人工确认”筛选只用于突出 AI 无法判断或旧人工结论需要更新的岗位，不限制其他岗位的复核资格。

## 岗位发现与鉴定依据的边界

在线简历页的“刷新在线简历”是唯一读取入口。只有用户点击后才模拟读取一次 BOSS：成功且内容变化时生成递增的“在线简历 vN”；内容未变化不递增；失败时保留旧版本并显示错误。岗位发现和岗位鉴定都不会自动刷新或重试读取 BOSS。首次没有任何版本时，“创建岗位发现”直接禁用，提示先手工刷新。

岗位发现不读取 BOSS，也不绑定岗位鉴定策略。它使用已经手工保存的在线简历版本确定搜索范围，并保存岗位和 JD。新岗位先保持 `assessment_status=not_queued`，此时没有鉴定策略版本。

一轮岗位发现从创建到完成固定使用开始时记录的一个在线简历版本，暂停恢复也不切换，运行中没有版本切换入口。若本轮使用 v1 时用户手工刷新得到 v2，在线简历页和岗位页顶部都会显示“当前已保存 v2；本轮发现仍使用 v1；v2 将用于下一次发现和尚未开始的岗位鉴定”。如需用 v2 重新初筛，只能等待本轮完成，或明确提前结束后再创建新运行。

新发现运行使用在线简历 v2，只表示本轮搜索范围基于 v2，不代表重复岗位已经用 v2 重新鉴定。再次发现已有岗位且 JD 判断内容未变化时，继续复用原来基于 v1 的最新有效 AI 结论与发送资格，岗位详情如实显示该结论实际基于 v1。只有岗位没有结论、JD 判断内容变化，或用户明确执行“重新鉴定”时，才会重新进入待鉴定状态，并在真正开始时使用届时当前版本。

手工或自动安排鉴定，只把岗位变成 `pending`。`pending` 只表示已经安排但尚未开始，不绑定或展示某个确定的在线简历、策略版本或 JD 副本。Worker 真正领取岗位为 `processing` 时，才使用数据库中最后一次手工保存的在线简历版本、届时当前策略和岗位 JD，并记录本次实际版本。等待期间在线简历从 v1 手工刷新为 v2、策略从 v1 改为 v2，尚未开始的岗位使用 v2；已经 `processing` 的岗位继续使用开始时的 v1。

“批量重新鉴定”的确认页只确认本批岗位进入待鉴定状态，不提供在线简历版本或历史策略版本选择。鉴定模块不读取发现运行使用的版本：岗位从 `pending` 被领取为 `processing` 时，直接采用届时当前已保存的在线简历版本。因此，同一时刻发现运行可以继续使用 v1，而尚未开始的鉴定使用 v2。岗位鉴定页只维护“当前策略”；岗位详情仅在执行中或完成后显示“本次实际使用：在线简历 vN、策略 vM”，不显示内部编号。Agent 收到的是该版本的完整在线简历内容，不是版本号或内部 ID。新实例自动创建并启用“默认策略 v1”，但它只属于岗位鉴定模块，不出现在岗位发现运行详情或创建确认中。

人工复核只积累岗位上的人工标注，连续复核任意数量岗位期间都是 0 次 LLM，也不自动生成或修改策略。当用户认为样本足够时，才在左侧“岗位鉴定”页面显式点击页首“生成新策略”；每次点击只模拟 1 次模型调用，输入生成这一刻正在启用的策略和这一刻已经存在、仍对应最新 JD 的全部人工正负标注，返回一份完整、可编辑、可直接采用的唯一候选稿，而不是零碎建议列表。候选稿弹窗用前端确定性的逐行 diff 标红删除内容、标绿新增内容；差异计算不调用模型，也不额外要求模型生成“主要变化”摘要。人工标注不要求岗位已有 AI 结论，也不因 AI 使用旧策略、AI 与人一致或 AI 判为不适合而排除；只有 JD 已变化、人工结论待复核的岗位才排除。AI“不适合”只作为 AI 鉴定结论展示。

防重复只依赖全局岗位的稳定 `platform_job_id`：同一稳定 ID 始终对应同一条岗位，再次发现直接读取这条岗位现有的鉴定和沟通状态，不创建副本。已有鉴定结论不会因再次发现而重复鉴定；已经真实沟通的岗位保留原 AI 与人工结论，但不能再次进入鉴定或发送处理。岗位关闭、稳定 ID 缺失、已经真实沟通只影响处理资格或反映平台事实，不是岗位“适合/不适合”结论。

候选稿只保存在当前页面会话的内存中。关闭、取消、离开岗位鉴定页、重新打开页面或重启原型后台后都不能恢复；这些动作以及在已有候选稿时重新生成，都会先展示“未采用内容将永久丢失”的二次确认。确认重新生成后，系统基于届时正在启用的策略和届时新增的人工复核标注再模拟 1 次模型调用，结果可能不同。用户可以直接编辑整份候选稿；编辑不代表模型结果未被使用，只有点击“采用此策略”才把当前完整文本创建并启用为新的正式策略版本。原型没有候选稿持久化文件、候选稿表或采用/放弃历史。

## 首次沟通边界

- 手工动作明确拆为“安排模拟沟通”和“安排真实发送”。
- 真实发送确认展示本批岗位数、完整固定招呼语和当前发送时间。
- 本批授权不会开启或修改全局自动首次沟通。
- 时间窗为空表示“全天可发送”，不是禁止发送。
- 点击“添加时间窗”后打开紧凑弹窗，可以一键采用“上午 09:00–12:00 / 下午 14:00–18:00 / 晚间 19:00–21:00”，也可以通过起止时间下拉自定义；不要求键盘输入时分，可以保存多个时间窗。
- 已经 `pending(simulation)` 或 `processing(simulation)` 的岗位不会中途转为真实模式。
- 开启自动首次沟通，表示持续授权当前所有仍有效的人机“适合”结论参与自动安排。在线简历或策略更新不会使历史岗位的最新有效结论失效，不会自动全库重鉴定、撤回已安排工作或增加二次确认；版本只用于追溯。只有新的鉴定完成、JD 判断内容变化、人工结论变化、岗位关闭等既有业务事件会改变当前判断或发送资格。

## 首次初始化

- 在线简历版本：无，必须先手工刷新；
- 自动岗位鉴定：关闭；
- 同时鉴定岗位上限：5；
- 自动首次沟通：关闭；
- 默认模式：Simulation；
- 固定招呼语：未配置；
- 真实发送时间：全天；
- 当前鉴定策略：默认策略 v1。

自动鉴定、自动首次沟通和招呼语设置不会阻止岗位发现；只有“尚无已保存在线简历版本”会阻止开始。同一原型进程内，页面重新打开和“重置模拟数据”会保留上次保存的设置与在线简历版本；完全停止并重启进程后回到演示数据。为了直接展示恢复中的运行，原型默认打开一个已有在线简历 v1 的实例；在线简历页可一键切换到“首次尚无版本”演示状态。
