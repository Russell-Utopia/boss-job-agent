# 领域文档

本仓库采用单上下文布局。工程技能探索代码库前，应按本文件读取领域资料。

## 开始探索前

- 读取仓库根目录的 `CONTEXT.md`。
- 读取 `docs/adr/` 中与当前工作相关的 ADR。
- 如果其中某个位置不存在，静默继续，不要仅因文件缺失而建议预先创建。

`domain-modeling` 技能会在领域术语或决策真正明确后，按需创建或更新这些文档。

## 使用领域词汇表中的术语

在工单标题、重构建议、假设和测试名称中使用领域概念时，必须采用 `CONTEXT.md` 定义的名称，不要改用其中明确要求避免的同义词。

如果需要的概念尚未出现在词汇表中，应先判断是否正在引入项目并不需要的新术语；如果确实存在领域缺口，则把它记录下来，交由 `domain-modeling` 技能处理。

## 标明 ADR 冲突

如果拟议工作与现有 ADR 冲突，应明确指出冲突，不能静默覆盖已有决策。例如：

> 与 ADR-0007 的既有决策冲突，但值得重新讨论，因为……
