# 真实打招呼默认关闭并显式启用

岗位发现、JD 持久化和全局队列流转可以真实运行，但真实打招呼默认关闭；只有求职者显式启用自动打招呼，或在全局岗位列表中批量选择并确认真实打招呼后，平台岗位才会通过 `JobPool` 进入打招呼队列。关闭自动打招呼只停止新的自动入队，不撤回已经入队的工作。`JobPool` 在入队和领取时、`PostService` 在实际打招呼前都必须确认最近一次可靠平台岗位状态为“可沟通”；没有设置打招呼时间窗时，`PostService` 可以在任何时间领取真实打招呼，设置后才限制在任一区间内领取。区间结束不打断已经开始的动作，可能已打招呼的只读对账不受时间窗限制。明确“已关闭”不得打招呼。动作前检查失败属于本次打招呼操作错误，不把岗位改成第三种状态，也不能继续执行外部动作。`PostService` 把页面业务证据和外部影响分类提交给 `JobPool`：能够确认没有打招呼成功时写入 `failed`，动作可能已经发生但无法确认时写入 `possibly_contacted`，完成对账前不得重试；技术错误写入持久化结构化运行日志。入队时冻结固定招呼语，避免界面关闭或设置变化改变已经排队的动作。随机抖动只用于控制节奏，不作为规避平台风控的手段。

开启自动打招呼前必须展示当前可进入真实队列的岗位数量、完整固定招呼语和当前打招呼限制，并由求职者确认；确认后只影响之后新符合条件的岗位。手工真实打招呼同样展示本批岗位数量、完整固定招呼语和当前打招呼限制；未设置时间窗时明确显示“全天可打招呼”。手工确认只授权这些选中岗位，不修改全局自动打招呼设置。

MVP 不提供模拟打招呼。删除理由及测试 Adapter、本地 live integration test 与真实打招呼产品能力的分工见 ADR-0024。
