# 真实打招呼默认关闭并显式启用

岗位发现、JD 持久化和全局队列流转可以真实运行，但真实打招呼默认关闭；只有求职者显式启用自动打招呼，或在全局岗位列表中批量选择并确认真实打招呼后，平台岗位才会通过 `JobPool` 以 `real` 模式进入打招呼队列。关闭自动打招呼只停止新的自动入队，不撤回已经入队的工作。`JobPool` 在入队和领取时、`PostService` 在实际打招呼前都必须确认最近一次可靠平台岗位状态为“可沟通”；没有设置打招呼时间窗时，`PostService` 可以在任何时间领取真实打招呼，设置后才限制在任一区间内领取。区间结束不打断已经开始的动作，可能已打招呼的只读对账不受时间窗限制。明确“已关闭”不得打招呼。动作前检查失败属于本次打招呼操作错误，不把岗位改成第三种状态，也不能继续执行外部动作。`PostService` 把页面业务证据和外部影响分类提交给 `JobPool`：能够确认没有打招呼成功时写入 `failed`，动作可能已经发生但无法确认时写入 `possibly_contacted`，完成对账前不得重试；技术错误写入持久化结构化运行日志。入队时冻结打招呼模式和固定招呼语，避免界面关闭或设置变化改变已经排队的动作。随机抖动只用于控制节奏，不作为规避平台风控的手段。

`simulation` 和 `real` 是单轮工作的执行模式，不是两个互斥的岗位终态。已经以 `simulation` 入队或正在执行的工作不会因设置变化中途变成真实打招呼；模拟完成后岗位记为 `simulated`，但它仍未发生外部沟通，之后可以在重新检查当前资格并取得真实打招呼授权后进入新的 `pending(real)` 轮次。真实模式启用时，自动入队既可以接收从未排队的 `not_queued` 岗位，也可以接收模拟完成的 `simulated` 岗位。只有 `contacted` 才表示这个岗位已经真实打招呼过，以后不再重复打招呼。

从自动模拟切换到自动真实打招呼必须先展示影响并由求职者确认。立即进入真实打招呼队列的数量只包括当前符合条件的 `not_queued` 和已完成模拟的 `simulated`；仍为 `pending(simulation)` 或 `processing(simulation)` 的岗位单独计数并明确提示“仍在模拟，本次不会进入”。这些在途岗位继续完成原模拟轮次；完成后若自动真实打招呼仍开启，再重新检查资格并自动进入真实打招呼队列。切换过程绝不直接改写在途工作的模式。

手工批量操作同样不能用一个含糊按钮依赖当前默认模式。MVP Web 分别提供“加入模拟队列”和“加入真实打招呼队列”；后台也分别接收模拟命令和带显式确认的真实打招呼命令，避免普通模式参数被误传。真实确认必须展示本批岗位数量、完整固定招呼语和当前打招呼限制；没有设置时间窗时显示“全天可打招呼”。确认只授权这些选中岗位，不修改全局自动打招呼设置。手工真实打招呼进入队列后遵守同一时间规则。
