# 采用本地个人运行边界

BOSS Job Agent v1 只服务求职者本人，在其 Mac 本地运行并复用已登录 BOSS 的 Chrome 会话。一个常驻 Go 后台进程持有 SQLite，并运行岗位发现、岗位鉴定和首次打招呼三个独立执行模块；MVP Web 只是操作界面，关闭界面不拥有也不清除执行状态。后台进程中断后，过期 Worker 租约用于识别失联的岗位发现运行和处理中岗位：岗位发现模块把失联运行写入 `failed`，`JobPool` 把失联鉴定写入 `failed`；首次打招呼如果可能已经执行外部动作，`JobPool` 则写入 `possibly_contacted` 并等待 `PostService` 优先对账，只有能够确认没有打招呼成功时才写入 `failed`。技术细节进入持久化结构化运行日志，不重复写入业务表。重新进入界面时，求职者可以重试原岗位发现运行，或明确提前结束后创建新运行。Chrome 不可用、登录失效或出现验证码时，依赖 BOSS 的发现或当前首次打招呼进入各自的失败状态，已经落库且可沟通的岗位仍可继续 AI 鉴定。
