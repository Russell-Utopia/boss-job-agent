# 只自动退出由本实例启动并可验证归属的 Pi 进程

`AdviceService` 按需启动专用于全局岗位鉴定队列的 Pi RPC 子进程，并为每个进程生成不可复用的运行标记。进程归属不写入 SQLite，也不建立 `managed_processes` 业务表；程序在自己的运行目录中为受管子进程原子创建临时标记文件，保存应用实例、Worker、PID、进程启动时间、可执行文件路径和运行标记，确认进程退出后再删除。进程可以跨多次全局鉴定请求复用，但每次推送的一组平台岗位使用隔离会话；全局岗位池不再有当前可领取的 `pending` 岗位或仍在处理中的鉴定工作时自动退出，未入队的 `not_queued` 和已关闭的 `pending` 岗位都不会让 Pi 空转，后续出现可领取工作再按需启动。

标记文件只是归属线索，不能单独授权终止进程。退出时先通过 RPC 或关闭输入请求优雅结束，等待有限时间后才向已验证的同一子进程或专属进程组发送终止信号。程序不得使用 `pkill pi`、按进程名搜索后批量终止，或停止并非由当前应用实例启动的 Pi、用户自己的 Pi 会话、Kimi WebBridge 守护进程及其他浏览器进程。应用重启后必须同时核对标记文件、PID、进程启动时间、可执行文件和运行标记以防 PID 复用；任何一项无法验证时宁可保留并报告疑似遗留进程，也不得尝试终止。

v1 同时最多运行一个受管 Pi 进程并只保留一个在途鉴定请求。“同时鉴定岗位上限”默认是五个且允许配置，表示 `assessment_status=processing` 的岗位数量，而不是 Pi 进程数；`AdviceService` 每次最多领取当前空闲名额数量的岗位放入同一个请求。调低上限不终止已经开始的岗位，只限制后续领取。未来可以增加有明确上限的鉴定 Worker，但每个 Worker 必须对应独立登记、独立标记和独立清理的 Pi 进程，全部 Worker 的在途岗位总数仍不能超过该业务上限。
