# MVP 不提供模拟打招呼

“模拟打招呼”最初用于防止尚未验证的岗位发现、鉴定和打招呼编排意外触发真实外部写动作，而不是求职者反复执行并据此作出产品内决定的独立任务。接口与模块 seam 明确后，这个风险应由测试解决：真实业务模块配受控 Adapter 验证状态、资格和调用次数；每个生产 Adapter 再通过显式本地 live integration test 连接真实外部数据源，接口稳定后还要运行全部生产 Adapter 组成的完整真实链路测试。

因此生产 MVP 删除 `simulation` 执行模式、`simulated` 岗位状态、模拟队列、模拟命令、自动模式选择和 Simulation 到 Real 切换。自动打招呼只表示持续授权新的合格岗位进入真实打招呼队列，默认关闭；手工与自动真实打招呼都保留影响预览、明确授权、资格重校验、动作前 BOSS 检查、时间窗、永久去重和 `possibly_contacted` 对账。测试 Adapter 不出现在 Web、自动化设置、领域术语或 SQLite 业务状态中。

默认 `go test ./...` 与 CI 完全离线，不要求 BOSS 登录、真实 Pi 或外部副作用。生产 Adapter 的 live integration test 只能通过单独的显式本地命令运行：岗位发现、在线简历、Pi 和打招呼 Adapter 分别验证自己的真实接口合同；完整真实链路测试使用全部生产 Adapter。真实 `SendFirstContact` 测试每次最多自动选择一个当前合格岗位，记录目标、招呼语、外部证据和 trace，并证明再次运行不会重复打招呼。运行该带副作用测试的显式命令就是本次授权；CI 将来即使取得 API Key，也必须重新评估成本、限额、凭证安全和外部副作用后才能纳入。
