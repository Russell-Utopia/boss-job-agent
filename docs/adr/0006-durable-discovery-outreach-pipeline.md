# 通过 SQLite 持久化队列连接岗位发现与首次打招呼

沟通任务采用“发现岗位、保存 JD、创建打招呼工作项、Worker 消费、回写结果”的持久化流水线，岗位发现与首次打招呼可以独立推进；v1 只运行一个发送 Worker，未来可在不改变任务模型的前提下增加 Worker。SQLite 同时保存岗位记录和打招呼工作项，暂不引入独立消息中间件。所有搜索范围耗尽只代表“发现完成”；只有发现完成且全部打招呼工作项都进入发送成功、模拟完成或按规则跳过的终态，任务才算“正常完成”。该选择增加了领取、重试和恢复状态的建模成本，但使浏览器执行中断后仍能继续，并避免把页面扫描速度与外部发送速度绑死。
